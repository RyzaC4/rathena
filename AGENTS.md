# AGENTS.md

## Cursor Cloud specific instructions

rAthena is a C++ Ragnarok Online MMORPG server emulator. The product is a set of
cooperating server daemons plus a MySQL/MariaDB database. There is no JS/Python
package manager; C++ third-party libs are vendored under `3rdparty/`.

### Services & ports

| Service | Binary | Port | Required | Notes |
|---------|--------|------|----------|-------|
| Database | MariaDB | 3306 | yes | schema/user/pass all `ragnarok`; root via unix socket (`sudo mysql`) |
| login-server | `./login-server` | 6900 (TCP) | yes | account authentication; entry point |
| char-server | `./char-server` | 6121 (TCP) | yes | character management; connects to login-server + DB |
| map-server | `./map-server` | 5121 (TCP) | yes | gameplay engine; connects to char-server + DB |
| web-server | `./web-server` | 8888 (HTTP) | optional | HTTP API (userconfig, emblem, party booking); not in docker-compose |

### Build (already configured by the startup update script)

- Configure then build: `./configure --enable-packetver=20211103` then `make -j$(nproc) server`.
  `make server` builds common/login/char/map/web + creates `conf/import` dirs.
- Build individual servers with `make login`, `make char`, `make web`, `make map`.
- The update script runs `./configure` on startup so `make` works immediately.

> `map-server` fails to compile because `src/map/skill.cpp` has a duplicate

### Database (MariaDB)

- systemd is NOT available in this VM. Start MariaDB manually:
  `sudo mariadbd-safe --datadir=/var/lib/mysql &` (data persists in the snapshot at `/var/lib/mysql`).
- Root access is via the unix socket: `sudo mysql`. The `ragnarok` DB, the `ragnarok`
  user (pass `ragnarok`, hosts localhost/127.0.0.1/%), and all schemas
  (`main.sql`, `logs.sql`, `web.sql`, `roulette_default_data.sql`) are already imported.
- To re-import from scratch, mirror `tools/ci/sql.sh` (it assumes root/root — adjust to
  `sudo mysql`). Item/mob tables are only needed if `use_sql_db: yes` (default `no`).

### Running the servers

- Run binaries directly from the repo root (they run in the foreground with an
  interactive console): `./login-server`, `./char-server`, `./web-server`.
  `./athena-start start|stop|restart` wraps all of them (it also tries to start
  `map-server`, which won't exist until the skill.cpp bug is fixed).
- DB connection defaults live in `conf/inter_athena.conf` and already point at
  `127.0.0.1:3306` / `ragnarok`. Local, gitignored overrides go in `conf/import/*.txt`
  (generated by `make import`). Example: `new_account: yes` in
  `conf/import/login_conf.txt` enables `_M`/`_F` account auto-creation on login.
- Inter-server auth uses the default `s1`/`p1` account (row in the `login` table).

### Tests / lint

- There is no unit-test or lint framework. CI validation = compiling the servers and
  running `./map-server --run-once` (see `.github/workflows/*.yml`). `--run-once` boots
  the map-server, loads all DB/scripts, then exits; it needs the DB running.

### Quick smoke test (login-server account creation)

With `new_account: yes` set and login-server running, a 55-byte `CA_LOGIN` (0x0064)
packet with a `_M`-suffixed username auto-creates an account and returns accept
(`0x0AC4`); verify with `sudo mysql ragnarok -e "SELECT * FROM login;"`.
